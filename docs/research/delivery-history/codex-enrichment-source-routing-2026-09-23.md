# Explicit enrichment source routing repair — 23 September 2026

The installed last30days 3.8.1 pipeline adds `jobs` to company/ticker queries after filtering the explicit `--search` request, then inserts it into every planned subquery. AlphaOS correctly requests `github,hackernews,polymarket,reddit,x,youtube`, but all 20 observed September 22 attempts also dispatched jobs. Nine attempts timed out at the unchanged 45-second deadline: four were still retrieving jobs, four were in `score_fun`, and one was reranking. This identifies avoidable unrequested work; it does not establish that all nine failures will be repaired.

The repository-owned default worker now honors the explicit request before planning and again after automatic job insertion. It filters the shared available-source list and plan, guards main/transient/thin-retry retrieval, and skips the deep supplemental X lane when X was not requested. Explicitly requested jobs remain permitted; unavailable requested sources are not invented. Requested source backends retain their existing internal enrichment semantics. Models, supplied context, rerank, `score_fun`, 45-second timeout, sources configuration, per-source caps and controls remain unchanged. The installed external provider is not edited.

The supported contract pins SHA-256 hashes of the installed entry script, routing pipeline and planner, validates hook signatures and binds imported modules to those verified paths. An unsupported provider update becomes unavailable before pipeline execution, requiring compatibility review. A source-policy violation remains a failed result even when upstream catches a retrieval exception. The default adapter additionally requires a completed policy receipt and refuses normalized clusters from any unrequested source. Explicit custom `LAST30DAYS_CMD` commands retain their behavior and are marked `unverified`; inherited policy flags cannot silently opt them in.
